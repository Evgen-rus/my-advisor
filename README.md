# My Advisor

Проектный скилл Codex для второго мнения. Основная модель выбирается в чате и отвечает за задачу. Советник работает в отдельной сессии на `gpt-6.2-astra` с reasoning `high`, получает конкретный вопрос и возвращает рекомендацию, риски и проверки.

## Требования

- Python 3.11 или новее. Скрипт использует стандартную библиотеку.
- Codex Desktop, CLI или IDE с доступом к GPT‑6.2 Astra и запуску подагентов.
- Вход в Codex через ChatGPT. Расход консультаций учитывается в текущем плане Codex. Пакету не нужны API-ключи.

## Установка

Один раз клонируйте исходники.

```sh
git clone https://github.com/Evgen-rus/my-advisor.git
cd my-advisor
```

Из папки с исходниками укажите корень существующего проекта.

**Windows**

```powershell
python .\my_advisor.py install "D:\Projects\My App"
```

**Ubuntu**

```sh
python3 my_advisor.py install "$HOME/projects/My App"
```

Скрипт добавляет `.agents/skills/my-advisor/SKILL.md`, `.codex/agents/my-advisor.toml` и маркированный блок в `AGENTS.md`. Файл `.my-advisor.json` хранит локальный учёт установки для удаления. Его можно исключить из Git, если установка нужна только на этой машине. Повторная установка проверяет существующую копию. При конфликте имён или при действующем `AGENTS.override.md` скрипт останавливается и сообщает причину.

После установки откройте новый чат Codex в целевом проекте. Конфиг проекта и выбор основной модели остаются под вашим управлением.

## Вызов советника

В чате Codex введите `$my-advisor` и вопрос, например «проверь, что запланированная миграция безопасна при одновременной записи».

Скилл также просит основную модель обращаться к Astra перед решением, которое может нарушить существующую работу, при неоднозначных изменениях БД, интеграций, очередей, планировщиков и параллельной обработки, после двух обоснованных неудачных попыток, либо перед завершением сложной задачи с конкретным непроверенным риском. Обычно хватает одного или двух вызовов. Простые правки модель выполняет самостоятельно.

Подагент получает контекст по вопросу, включая относящиеся к нему фрагменты файлов, diff и результаты проверок. Он консультирует, а основная модель проверяет выводы и выполняет работу. Если клиент позволяет указать именованную роль, Codex использует установленный TOML. Если клиент предлагает только выбор модели и reasoning, Codex запускает отдельную Astra с теми же инструкциями из шаблона. Если выбранная основная модель или клиент не позволяют запустить Astra 6.2 на High, Codex сообщает, что консультация недоступна.

Подагенты наследуют права родительской сессии. Роль отключает поддерживаемые инструменты и предписывает Astra работать только по переданному контексту. Вариант запуска через выбор модели передаёт инструкции в задаче подагента.

## Удаление

**Windows**

```powershell
python .\my_advisor.py uninstall "D:\Projects\My App"
```

**Ubuntu**

```sh
python3 my_advisor.py uninstall "$HOME/projects/My App"
```

Скрипт удаляет принадлежащие пакету файлы и его блок из `AGENTS.md`. Изменённые вручную компоненты сохраняются с сообщением о конфликте. Учёт сохраняется, пока есть конфликт. После чистого удаления повторный запуск сообщает, что удалять нечего.

Версия Astra зафиксирована в скилле и шаблоне агента. Для ручного обновления скачайте нужную версию исходников, удалите предыдущую установку и установите пакет снова.

## Проверки

```sh
python -m unittest discover -s tests -v
```

Тесты создают временные проекты с пробелами в пути и проверяют повторную установку, конфликты имён, сохранение ручных изменений и точное восстановление обычного `AGENTS.md`. Для проверки живой консультации откройте проект с установленным скиллом, вызовите его на примере без записи и проверьте отдельный подчат и метаданные его модели.
